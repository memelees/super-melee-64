SM64 with native Melee fighters — agreed product target
23 October 2026

The game is Super Mario 64's adventure, with playable Melee/Akaneia fighters.
SM64 owns courses, objects, enemies, coins, stars, doors, warps, save progress,
bosses, lives and the ending. A terrain import in Melee is a development fixture
and does not satisfy the product target.

Rendering direction confirmed in the architecture discussion: SM64 supplies the
authoritative gameplay camera and world depth. Melee should draw its characters
and relevant effects without a duplicate visible map or autonomous gameplay
camera. Preserve native character appearance. The chosen architecture is one operating-system game process.
INTEGRATION-RESEARCH.txt records source comparisons, integration details and
the proposed native rendering/depth proof. The native character/item pass now replaces the bone/vertex-color preview.

Single-player acceptance: start a native desktop SM64 save as Link, progress
through its courses and bosses, save/reload and reach the ending. Cover the full
star catalogue and identify any character-specific traversal blockers. Preserve
SM64's progression and interactions while the selected fighter retains its own
Melee moves and physics. Expand to the existing Melee3D playable roster,
including Akaneia additions such as Sonic.

Multiplayer acceptance: the same adventure and fighter behavior in Coop Deluxe;
fighters can battle using actual Melee damage percentages, hitboxes, knockback,
grabs and throws. Joining, leaving and ownership must preserve consistent state.
The standalone native port and the co-op port are both targets.

Agreed world adapters: coins heal percentage; Melee attacks affect SM64 enemies;
doors can open without bespoke fighter animation; water now requires slow
sinking, kicks, usable specials and SM64 air/drowning rules. Cannons retain an
SM64-scale launch arc with Melee tumble; wing caps and shells use SM64 travel.
Other scripted world actions can use SM64 behavior. Defer custom projectile effects. Use SM64's normal world behavior as
the default when an interaction has no fighter-specific implementation.

Current integration gates include native rendering/simulation, live collision,
projectile impacts, traversal, moving platforms, doors, painting entry and star
save/reload. See the current verification report for the exact tested scope.
The imported Castle Grounds fixture is useful for movement/combat comparisons,
but cannot establish any adventure or game-completion acceptance.

Current implementation and limits are in STATUS.txt. Two-client native combat,
shared encounters and level handoff pass; the 16-player capacity is supported.
Both Windows hosts compile. No full-game/all-roster clear, sixteen-person live
session, or actual Windows runtime certification has been established.

Audio preference: use SM64 world music, with native Melee character voices and
sound effects. Disable the donor Melee soundtrack in the embedded runtime.
Combat presentation: render the native Melee percentage HUD and use native
percentage/weight-dependent launches in place of ordinary SM64 combat HP loss.

Additional traversal/presentation targets (24 October 2026): steep hills should
use SM64 sliding rules without falling through the ramp; respawns should use
Melee's actual platform; preserve native character/item effects and sounds while
keeping Melee music muted. Current verified scope is in environment-update.json.
